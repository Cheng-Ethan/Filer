# Internationalization (i18n)

filer ships with English (`en`) as the authoritative source and Simplified
Chinese (`zh-CN`) as a complete translation. Locale files live in
`dls/locales/` and are discovered automatically at startup.

## Files

```text
dls/i18n.py              locale loading, negotiation, rendering, validation, plugin locales
dls/locales/en.json      authoritative key set (English)
dls/locales/zh-CN.json   complete Simplified Chinese translation
tests/test_i18n.py       locale integrity and language negotiation tests
```

Each locale file has this shape:

```json
{
  "_meta": { "name": "한국어", "code": "ko-KR", "dir": "ltr" },
  "app": { "title": "filer" },
  "common": { "back": "뒤로", "download": "다운로드" }
}
```

`_meta.code` must match the file name (`ko-KR.json` → `ko-KR`).
`_meta.dir` is reserved for future RTL support.

## Adding a language

Using Korean as an example:

1. Copy the authoritative file:

   ```bash
   cp dls/locales/en.json dls/locales/ko-KR.json
   ```

2. Edit `_meta` in `ko-KR.json`:

   ```json
   { "name": "한국어", "code": "ko-KR", "dir": "ltr" }
   ```

3. Translate every value. Keep the key names and placeholders unchanged.

4. Validate the locale:

   ```bash
   python3 -m dls.i18n check
   ```

5. Run the test suite:

   ```bash
   python3 -B -m unittest discover -s tests
   ```

6. Restart the service so the new locale file is loaded:

   ```bash
   sudo systemctl restart filer.service
   ```

The language selector appears automatically when more than one locale is
available. A user can switch languages from the top toolbar; the choice is
stored in the `filer_lang` cookie. Without a cookie, the server uses the
`lang` query parameter, then `Accept-Language`, then falls back to English.

## Translation rules

- Do not change key names.
- Keep every `{placeholder}` exactly as it appears in `en.json`.
- Do not add leading or trailing whitespace to values.
- Missing keys fall back to English at runtime, but `check` and the tests
  require a complete key set.
- Prefer short UI labels. Long translations are allowed; buttons grow with
  their text instead of using a fixed width.

## Plugin locales

Plugins can register a `locales/` directory:

```python
def register(ctx):
    ctx.register_locale(os.path.join(ctx.dir, "locales"))
```

Each `*.json` file is flattened and merged under the
`plugin.<plugin-id>.` namespace. For example:

```json
{
  "title": "Todo editor",
  "save": "Save todo list"
}
```

becomes:

```text
plugin.todo-editor.title
plugin.todo-editor.save
```

The current language and English fallback are both merged. Plugin locale
files are not validated by `python3 -m dls.i18n check`; plugin authors should
keep their own keys consistent and test both languages.

## Behaviour and limitations

- Language priority: cookie `filer_lang` > query `lang` >
  `Accept-Language` > `en`.
- Prefix matching is supported: `ko-KR` can match a `ko` locale, and
  `zh-TW` matches `zh-CN` when no `zh-TW` file exists.
- `en` is always the fallback locale.
- Plural rules and RTL layout are not implemented yet. The current
  formatter only supports `{name}` interpolation.
- Korean font fallbacks are included in the shared UI font stack.
  Other scripts may need additional fonts in `dls/ui.py`.
- Only the current locale, including plugin translations, is injected into
  the browser as `window.I18N`; the full locale catalogue is never sent to
  clients.
- Locale discovery happens at startup. Restart the process after adding a
  core locale file or installing a plugin.
